## 1. サービス概要（※最後に書いてOK）
- このサービスはどんなサービスか（3行以内）

  ドローン運営管理ツール

- 誰の、どんな課題を、どう解決するか

  個人ユーザの国交省(DIPS)情報の転記入力ミスや記入漏れ不安の解消

  記入項目内容がそれぞれバラバラに管理され、一元管理されない。

  個人がアプリを使わなくなってしまい、ドローンの運行日誌の管理が雑になってしまう。

## 2. このアイデアはどこから生まれたか 
### 2-1. きっかけとなった体験・感情
このアイデアの元になった
**自分自身の体験・感情・違和感**を教えてください。

  - 2025年に無償アプリを使用してドローン飛行日誌及び整備報告書を作成していた。 アプリのバージョンアップに伴い、データが消去されて困った。
  - 飛行練習中に見回り中の警官に日誌を提示を求められたときの法規違反の可能性に恐怖した。

## 3. 課題の整理
### 3-1. 表に見えている困りごと
  -  現場で数タップするだけで、国交省（DIPS）への報告に必要な項目を漏れなく記録する必要がありExcelへの転記ミスのストレスや、報告漏れの不安を解消します。
  -  機体、バッテリー、飛行時間をそれぞれバラバラにExcelで管理するのが限界。
     自動で一元管理できる。

### 3-2. 本当に解決したい課題は何か
  -  個人が嫌々義務で記録するのではなく、進んでアプリを使いたくなるような心理的な
     負担の軽減。

   このアプリだけでなく、他にも色々なドローンアプリを作り、プログラミング能力が向上した暁
   にはドローン総合アプリでまとめて一括管理したいと思い、まずはこちらのアプリを作成したいと考えました。

## 6. このサービスで提供したい価値
### 6-1. ユーザーの変化
 - 今まで紙やEXCELなどで管理していたが、操作簡単で「直感的に使えるし」「無料で使えるなら」本サービスへ移行するメリットを感じてもらえる。

### 6-2. 価値を一文で表す
 - 情報管理が苦手なユーザが、必要項目の記入漏れや、データの記録3年保管義務などのデータ管理
   から解放され、アバター育成機能をほっこり楽しみながら義務感からではなく自分で記録したくなるような、ユーザにやさしいアプリケーションである。

## 8. このアプリの懸念点とその対策
### 懸念点①

    卒業制作が期限内で作成が間に合うかを懸念している

- 何が問題になりそうか：

  READMEのやり取りに現在2～3WEEKかかっている。
  コミュニケーション的に時間がかかる事が問題と思っている。

- なぜそう思うか：

  README以外の課題が4つ残っている。同様な時間がかかると想定すると、
  2.5WEEK * 4 = 10weekで約2.5か月がレビューのやり取りと想定されると、

  卒業期限3か月 - 2.5か月より、実質コーディング対応は0.5ヵ月となります。そのため、期限内で作成が間に合うかが懸念事項と考えている。

- そのために考えている対策：

  急に理解度や企画力を上げることは困難である。実質コーディング作業内容を減らすために、何をMVPから外してスコープを絞るかの対策を検討しても0.5か月に合わせる内容絞るのはあまり有効には思えない。

  - 対策1

    いかに効率的にコミュニケーションを密にとり、企画書を通すことを対策案と考えている。
  
    レビューやり取りのタイムスケジュールから下記のサイクルが最適であり、このレビュー
    提出スケジュールで、アドバイス内容を吟味して回答することが効率になると思われる。

    ①10:00まで提出 ⇒  午前中返却
    ②18:00まで提出 ⇒  20:00返却 

    難しいアドバイス内容の場合、1回スキップしてでもよいので十分吟味して回答することで
    余計なやり取りが発生させない方が全体最適が可能と思われる。

  - 対策2

    レビューやり取りの隙間に次課題や実装内容の検討を進める。
