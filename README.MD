## 1. サービス概要（※最後に書いてOK）
- このサービスはどんなサービスか（3行以内）

  ドローン運営管理ツール

- 誰の、どんな課題を、どう解決するか

  ドローン仲間のためのメーカ都合バージョンアップしてもデータが消えず、ネット未接続でも
  操作できる。

## 2. このアイデアはどこから生まれたか
### 2-1. きっかけとなった体験・感情
このアイデアの元になった
**自分自身の体験・感情・違和感**を教えてください。
  
- 2025年に無償アプリを使用してドローン飛行日誌及び整備報告書を作成していた。 アプリのバージョンアップに伴い、データがまっさらになってしまっていた。

---
### 2-2. なぜそれが「気になった」のか
**なぜ自分はそれが気になったのだと思いますか？**

- 飛行練習中に見回り中の警官に日誌を提示求められたときに、法規違反になってしまうため。  
---

## 3. 課題の整理（表面的になっていないか）
### 3-1. 表に見えている困りごと
  (1)飛行日誌及び整備日誌は紙か電子データの携帯義務があり、警察に提示できない場合、刑罰となってしまう。
  (2)国土交通小省更新時及び国家資格のライセンス取得時にトータル飛行時間が規定されており、正確な時間として使おうと思っていた。

その体験の中で、最初に感じた「困りごと」は何ですか？

 - データが消えたらとんでもないことになると業者なら理解されていると思っていたが、その認識がずれていた。
 - データのバックアップができなかったと記憶している。
---

### 3-2. 本当に解決したい課題は何か

- 山間部だとネット電波拾えず、アプリ入力できない可能性がある。
- 解決手法の案として、PWA (Progressive Web App)でローカルにデータ保存し、別途オンライン時に同期させる方法を考えている。
---

## 8. このアプリの懸念点とその対策
### 懸念点①
- 何が問題になりそうか：
  オフラインでの対応機能対応が出来るか少し心配である。

- なぜそう思うか：
  サーバにアクセスして操作する教材が主であったため、ローカルで対応について
  やったことがないため。

- そのために考えている対策：
  ローカル時はRAILSとDATABASEの代わりに、PWA（Progressive Web Apps）で対応。
  クラウドと接続時にローカル時のデータを同期ボタンで反映できるようにする。

---

### 10-2. 技術選定の理由
- なぜこの技術を使うのか

  ①1度練習でデプロイをRender+Neon実施した経験があるため。また無償であるため。

  ②TailwindとBootstrapを同じよう装飾確認した。どちらが優れているという結果で
    なかったので併用を考えている。

  ③画面表示部を先に作成・表示させ、そちらを組み合わせて作り込む方法を考えております。
    その場合、html+javascript+cssで作成したあとに展開させるので、Reactの方が扱い
    やすそうだと判断しました。

- 今回チャレンジしたい点

    本リリースにてPWA（Progressive Web Apps）の対応すること。

- 不安な点

  ①バックエンドとフロントエンドが干渉が起きないか。
  ②Bootstrapと他javascriptと干渉が起きないか。
  ③Reactの画面更新トラブルでのデバックに時間がかかりすぎないか。
